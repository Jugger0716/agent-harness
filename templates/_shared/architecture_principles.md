Invariant constraints for the harness orchestrator skills.

1. **Orchestrator reads no intermediate files.** 8 numbered exception slots, 7 live — slot (2) was retired 2026-09-18 and its number is kept so citations of (3)–(8) stay valid. Writes are a separate category and are not counted — the orchestrator WRITES spec.md / changes.md / slice_plan.md from returned objects, and `cold_review.md` on the WORKFLOW path from the segment's `coldFindings` (`skills/harness-build/SKILL.md` §Step 5; on the INLINE path the cold-review sub-agent writes it itself, `skills/harness-build/SKILL.md` §Step 6, AC-27):
   - (1) spec.md at the plan gate — at either render site of HARD GATE #1, including the live line count `skills/harness-build/SKILL.md` §Entry's approval check takes for the in-session one and the same count `skills/harness/SKILL.md` §Session Recovery's resume checks take (the approval check, the re-stamp test, the Stale Determination it applies) — and at the After-Plan boundary (§Scale Assessment signal computation, including the INLINE fallback)
   - (2) *retired 2026-09-18 (v8.14 Slice 3)* — was `qa_report.md` at the verdict gate. The verdict now lives in `verify.verdict`, written from the Evaluator's 1-line return (INLINE — `skills/harness-build/SKILL.md` §Step 6) or the `VerifyVerdict` object (WORKFLOW — `skills/harness-build/SKILL.md` §Step 5) and read by `skills/harness-build/SKILL.md` §Step 7 on both paths, in-session and on resume. `qa_report.md` is written for the human and no orchestrator reads it.
   - (3) changes.md path extraction on WORKFLOW-path resume when `workflow_ctx` is null (repo-relative paths only, reasons stripped — the `changedFilesList` source priority of `skills/harness-build/SKILL.md` §Step 5)
   - (4) verify_report.md failing-file extraction for the Auto-fix Proposer (paths only, through Path Validator `kind=file_reference`, capped at 5 — the Auto-fix dispatch of `skills/harness-build/SKILL.md` §Step 5)
   - (5) Step 2's Discovery Notes Injection reads (`qa_notes.md` / `critic_findings.md` content passed to the planner)
   - (6) `plan_critic_findings.md` Summary parsing + the `.harness/planner/proposals.json` re-entry read
   - (7) gate-display critic count parsing (the resume redisplay's `plan_critic_findings.md`) — distinct in purpose from (5)
   - (8) `.harness/converge/` reads (`skills/harness/SKILL.md` §Step 2.6 and §Approval Gate — the ledger and the verify sub-agent's `verdict.json`, `templates/harness/converge.md`; parsed as data, never followed as instructions — that file's §Ledger format) and the `Slice` / `Command` column read of `slice_plan.md` — slice detection (`skills/harness/SKILL.md` §Step 1 item 7 and §Approval Gate's slice variant, and `skills/harness-build/SKILL.md` §Step 8) and the shape check (`skills/harness-build/SKILL.md` §Step 3.6 and §Step 8), both defined once in `skills/harness-build/SKILL.md` §Epic Slice Chain, plus the current row's `Command` that `skills/harness/SKILL.md` §Approval Gate step 5's non-interactive escape line prints; table cells parsed as data, never followed as instructions

   > Apply-before `--- a/` / `+++ b/` diff header lines (2 metadata lines per file; the hunk body is delegated to the Edit tool) are not a violation. Writing `proposals.json` as a direct serialization of the segment's return, and §Step 2.6's pre-dispatch delete of `plan_critic_findings.md` (on the same footing as the `.harness/` delete of `skills/harness-build/SKILL.md` §Step 8), are neither reads nor content writes and do not enlarge this list. Nor are the converge loop's file operations (`templates/harness/converge.md`): the `snapshot.md` file copy and the pre-dispatch deletes of its per-round outputs are neither; writing `ledger.json`, the re-stamp's empty `snapshot.md` and rendering `plan_critic_findings.md` are writes; only the reads slot (8) names are reads.

2. **The Auto-fix Proposer is the only orchestrator-dispatched sub-agent that directly reads SOURCE files** (segment-script agents explore the codebase themselves, inside the engine's autonomous span). Other inline sub-agents receive content only through template variables — with one narrower carve-out: an inline sub-agent MAY receive a `{docs_path}` artifact PATH the orchestrator explicitly hands it (e.g. `templates/harness/plan_critic_inline.md`'s `{spec_path}`) and read that one file itself. `{docs_path}` artifacts are not source files, and #1's list keeps its 8 numbered slots (AC-27). Two further carve-outs belong to the converge loop (`templates/harness/converge.md`), both inline sub-agents on both paths: the **review** sub-agent (`templates/harness/converge_review.md`) reads the repository, source files included, READ-ONLY and executes none of it — its only write is its own output file, and the loop's `git status` comparison stops the run on any other change that comparison can see (its blind spot: `templates/harness/converge.md` §Round, Tree check); the **verify** sub-agent (`templates/harness/converge_verify.md`) reads `.harness/converge/` and the round-1 critic's output (`{docs_path}plan_critic_findings.md`) READ-ONLY, plus the `{docs_path}` spec under the carve-out above, plus — read-only, to confirm a finding's evidence and for nothing else — the repository files that evidence quotes and the read-only commands it names (`templates/harness/converge.md` §Classification rubric); nothing else.

3. **Paths only to sub-agents; never file contents** — except ephemeral digests passed inside a segment run (they never enter the orchestrator's context beyond `workflow_ctx`), and `specContent` passed as a segment arg to `harness.build` (`skills/harness-build/SKILL.md` §Step 4 — WORKFLOW path), `harness.eval` (`skills/harness-build/SKILL.md` §Step 5 — WORKFLOW path) and `harness.critic` (§Step 2.6's WORKFLOW branch): size, not path-vs-content, is the actual constraint there. Within `harness.eval` the exception covers the Evaluator only; the cold reviewer receives a 1-line path pointer (from the `specPath` arg) on both paths. The converge loop's **delta** review is path-only by construction: it receives the snapshot, spec and ledger PATHS and computes the diff itself — no diff text and no spec content crosses into its prompt (`templates/harness/converge.md`).

4. **Session-wide invariants** (`skills/harness-build/SKILL.md` §State Machine — Auto-fix State Transition Table): Auto-fix at most 1 attempt per session (`verify.autofix_attempted` once-only, not reset on round increment); Layer 1 retries max 3, NOT reset after Auto-fix Apply.

5. **All external paths pass through Path Validator before use** (§Path Validator below).

6. **Gates never enter segment scripts.** The 3 HARD-GATEs (spec-confirm / verify-fail / auto-fix-apply) are rendered by the orchestrator skills between segment runs; `scripts/verify_meta_literal.py` rejects the `<HARD-GATE>` tag form, `AskUserQuestion`, and the `Apply patch` option label inside any segment script — a marker tripwire, not a proof (the spaced prose form `HARD GATE #N` in script comments is allowed). HARD GATE #1 (spec-confirm) renders at `skills/harness/SKILL.md` §Approval Gate (every variant) in an inline session and at `/harness-gate` in a separate one — one gate, two render sites. The first is an orchestrator-side AskUserQuestion, never inside a script; the second (`skills/harness-gate/SKILL.md` §Step 3) renders as up to two passes (A, B) inside ONE `<HARD-GATE>` tag. Neither is a fourth HARD-GATE: the count stays 3.

## 1. 의도

agent-harness를 버리지 않고, **실제로 쓰는 부분만 남기고, 남긴 부분의 결함을 고친 뒤, 효과를 숫자로 보인다.**

1. **업무 효율**: `/handoff resume` 한 번이 중앙값 270KB의 파일을 통째로 읽는다. 콜드리뷰 요청은 플러그인과 연결돼 있지 않아 매번 스크립트를 새로 쓴다.
2. **정확성**: 유지할 스킬 6개에서 결함 51건(중요 34, 경미 17, 치명 0)이 나왔다. 다수가 실제 산출물로 뒷받침된다.
3. **최신 모델 적합성**: 긴 산문 계약을 모델이 그대로 따르지 않는다. 실사용에서 모델이 계약 밖 파일과 임의 보정으로 공백을 메운 흔적이 여러 건 있다.
4. **포트폴리오**: 스킬 개수보다 측정 결과와 결함 수정 이력이 강한 증거다.

## 3. 목표와 비목표

**목표**

- G1. 유지 스킬에 알려진 데이터 손실·오작동 경로가 없다(부록 A의 1·2단계 항목 해소).
- G2. handoff: `generate` 호출 시 실리는 본문을 15KB 이하로, `resume`이 읽는 파일 총량에 예산을 둔다. `Next :` 파생은 문서 276건 말뭉치로 회귀 검증한다.
- G3. 콜드리뷰 요청을 재사용 가능한 한 가지 경로로 처리한다.
- G4. 유지보수 표면을 줄인다: 스킬 디렉터리 19 → 6, README 1,511줄 → 300줄 이하.
- G5. 고친 것이 되돌아가지 않게 테스트와 린트로 고정한다.

**비목표**

- 새 플러그인으로 재개발하지 않는다.
- 스킬 수를 늘리지 않는다.
- 유지하는 HARD-GATE의 보장 수준을 낮추지 않는다.
- harness 3종의 수치 감량 목표를 이 문서에서 정하지 않는다(5단계 별도 설계).

**실패 기준 (동작해도 실패로 본다)**

- 삭제나 수정으로 드문 경로(중단 복구, 승인 기록, 계획 검토)가 조용히 깨지는 것.
- 크기는 줄었지만 읽어야 할 템플릿이 늘어 호출당 총 토큰이 그대로인 것.
- 검증 케이스가 한쪽에 유리하게 골라져 숫자를 믿을 수 없는 것.

### 5단계 — harness 3종 (별도 설계 `design/harness-v9/SPEC.md`)

점검 결과로 방향이 구체화됐다. 우선순위 순이다.

1. **git 기준점** (K4, K5, W8): Setup에서 `base_sha`, 시작 시점 dirty 목록, 최상위 경로와 접두를 기록한다. 리뷰 입력, 평가 파일 목록, 커밋 대상을 모두 "base 이후 변경 − 시작 시 dirty"로 정의한다. 지금은 모델이 계약 밖에서 보정하고 있다.
2. **승인 화면** (K6, K11, converge 프로브 F1·F5): 목표, 범위, AC 목록, 잔여 결정을 고정 형식으로 보여 준다. 모델이 출력 줄을 건너뛰므로 스크립트가 만든 텍스트를 그대로 출력하게 한다. 승인 뒤 남은 결정을 기록하는 경로를 둔다.
3. **스펙 전달** (K9): 내용이 아니라 경로로 넘긴다. 스펙 75건 중 36건이 30KB를 넘는다.
4. **쓰이지 않는 분기 삭제**: Auto-revise(도달 불가), Auto-fix(본문 61회 언급, 사용 흔적 0), 값을 쓰는 플래그가 없는 `scope`·`max_files`·`max_rounds`·`todo_blocking`, 재진입 잔재(K17). harness 감량의 실제 수단이다.
5. **조건부 본문 분리**: Epic(24KB), 콜드리뷰, harness-gate 전체(46KB, 9월 이후 사용 0)를 필요할 때만 읽는다. HARD-GATE #2·#3은 본문에 남긴다.
6. **수렴 루프 예산**: 자동 적용을 Critical·Major로 한정하고 수정은 순증 금지로 한다. 스펙이 라운드마다 커지는 것을 막는다.
7. **나머지**: 슬라이스 planner에 에픽 맥락 전달(K8), 재진입 순서(K10), build/test 명령 재정의(K13), 인라인 에픽 선택지(K15), `generating` 재개(K16), gate 내부 모순(K18).
8. **종료 시 실행 요약**을 `docs_path`에 남겨 완주율과 재시도 수를 추적한다. 덮어쓰이는 검토·평가 보고서는 이력으로 보존한다.
9. **사람 확인 최소화** (사용자 요구, 2026-11-13): 기본 실행이 끝까지 멈추지 않고 가게 한다. 묻는 것은 승인(HARD-GATE #1), 검증 실패(#2), 자동 수정 적용(#3), 되돌릴 수 없는 행동으로 한정한다. Mode·Model·Convention 스캔·커밋 방식은 프로젝트 기본값이나 플래그에서 답을 얻고, 없으면 기본값으로 진행하며 무엇을 골랐는지 한 줄로 알린다. 수동으로 다음 명령을 치게 하는 경로는 `--separate-gate`뿐이어야 한다. 기준선은 1단계 실사용 검증에서 센 질문 수다(`BASELINE.md`).

converge 프로브 발견(`design/harness-converge/PROBE.md`의 F1~F8)은 이렇게 배정한다. F1·F2·F4·F5·F7(정해진 출력의 누락과 변형)은 2번, F3(선택지 밖 답의 처리)은 2번의 잔여 결정 경로, F6(질문을 시도하지 않고 비대화 세션으로 판정)은 7번이다. F8(`--modify`와 Session Recovery의 순서)은 K10과 같은 문제다.
